# الجلسة 006: فتح واجهة الويب

التاريخ: 2026-10-09 — America/Toronto.

## طلبات المستخدم المتاحة

> ما سم الموديل التي تم استعماله

> هل تم فتح الواجهة لتجربته ام هو عبارة على terminal فقط

> جيد افتح الواجهة الويب

## التوضيح والتنفيذ

- النموذج المستخدم هو Qwen3 4B Instruct بضغط Q4_K_M، باسم محلي `my-agent:4b`. التخصيص الحالي إعدادات ورسالة نظام؛ لم يبدأ تدريب الأوزان.
- كان التشغيل السابق في Terminal. بناءً على الطلب الجديد، شُغلت واجهة Hermes dashboard الأصلية وفُتحت صفحة المحادثة في المتصفح على `http://127.0.0.1:9119/chat`.
- أضيف `start-web.command` لإعادة تشغيل الواجهة باستخدام `start-hermes.command` وبيئة PM ومجلد البيانات الحالي. الخادم مرتبط بـ127.0.0.1، ولا توجد خدمة بدء تلقائي عند تسجيل الدخول.
- بنى المشروع ملفات الويب وجهز اعتماديات Node عبر آليته الأصلية. واجهة المحادثة تضم TUI الأصلي عبر PTY؛ لم تُبنَ واجهة محادثة بديلة.
- بيانات التشغيل والسجلات ورموز المصادقة والأوزان محلية خارج المستودع العام. تحديث GitHub يشمل ملف التشغيل وذاكرة التطوير فقط.

## التحقق

- فحص Bash ومساعدة أمر dashboard. إعادة تشغيل الملف اتصلت بالخادم الموجود بنجاح وأعادت فتح المتصفح.
- صفحة `/chat` وجميع ملفات JavaScript/CSS الستة عشر أعادت HTTP 200.
- نجح طلب `/api/config` بمصادقة الرمز المؤقت، وأكد النموذج `my-agent:4b`؛ لم يُطبع الرمز أو يُحفظ في الوثائق.
- نجح الاتصال المصادق بـWebSocket الخاص بـPTY وظهرت شاشة المحادثة بالنموذج `my-agent:4b`.
- لم يُرسل طلب استدلال جديد أثناء فحص الويب؛ الرد الفعلي وحفظ SQLite سبق التحقق منهما في الجلسة 005. لم يُجرَ تقييم بصري آلي للمتصفح أو تدريب جديد.

## الاستمرار

جرّب المحادثة من المتصفح. الرد الأول قد يستغرق عدة دقائق على Intel CPU. راجع [دليل التشغيل](../RUNNING.md) و[التسليم](../HANDOFF.md) قبل تعديل النموذج أو توسيع الأدوات، وأكمل خطة حماية البيانات والنسخ والاستعادة.
